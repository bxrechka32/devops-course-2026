# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на коммит (файл с хешем в `.git/refs/heads`). Она создаётся и переключается мгновенно, локально, без сети и без копирования файлов.
В SVN ветка — это копия каталога на центральном сервере (`svn copy trunk branches/...`). Операция идёт через сеть, а при слиянии нужно отслеживать, какие ревизии уже влиты (`svn:mergeinfo`). Поэтому ветки в SVN создают редко и сливают болезненно.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: история и номера ревизий хранятся только на сервере, у разработчика есть лишь рабочая копия. Коммит — это отправка изменений на сервер, который присваивает новую ревизию, поэтому без соединения коммит невозможен.
В Git коммит сохраняется в локальный репозиторий, а на сервер отправляется позже через `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Большие бинарные файлы (игровые ассеты, CAD-модели, видео): можно выкачать только нужный подкаталог, не храня всю историю локально, и заблокировать файл (`svn lock`), чтобы двое не правили один бинарник.
- Большие монорепозитории со строгими правами доступа на уровне отдельных каталогов.
- Legacy-проекты, где перенос истории и переобучение команды дороже, чем выгода от перехода.
- Процессы, которым удобна простая линейная история с последовательными номерами ревизий (аудит, работа не-программистов).
